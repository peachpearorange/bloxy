# Bloxy
A browser-first multiplayer voxel sandbox in Bevy 0.19.1, aiming at the feel of big modded block-building packs: a procedural ocean of diverse islands with ores, caves and trees, waystones to travel between them, mining and building, other players around you, and (later) machines, power and automation. Everything is procedural: no mesh or texture assets.

# Roles
`protocol::Role` (from opts): `Solo` (no network, local authority), `Host` (native window + WebSocket server), `Dedicated` (headless server, `MinimalPlugins`), `Guest` (connects to a server; the browser build is usually this or `Solo`). `authority` systems run for every role but `Guest`; `plays` systems for every role but `Dedicated`. Use these, not replicon's states, to gate game logic: replicon's `ClientState::Disconnected` also covers a guest that lost its connection.

# Modules
- `block.rs` — `Block` (u8 repr, append new variants so saves and the wire keep their meaning; `look` → `Opaque/Cutout/Liquid/Invisible/Model/Log`, `leafy`, `modelled` (flowers, saplings, small mushrooms: every variant from `Poppy` on, `ALL_MODELS`; not solid but targetable, break at once), `fluid` (water, lava: swum in, not solid), `solid`, `breakable` (not bedrock or waystones), `seconds_to_break`, `drop`, `tiles` = top/side/bottom `Tile`s). Add a block: variant + every match, and a `Tile` with its `paint`.
- `noise.rs` — integer-hash value noise and Perlin (`perlin2`, `perlin3`, `fbm2`, `unit`, `hash`). Only `+ - * floor` and integer ops, so wasm and native generate bit-identical worlds; never use `sin`/`exp`/`powf` in anything that feeds generation.
- `island.rs` — the archipelago: one `Island` (or none, 8%) per `CELL` (128 blocks) square, centre jittered, cached by `Island::at(seed, cell)` (`within(low, high)`, `near(at)`, `beside(at)` = the island whose waystone is within reach). Random per cell (`key` hashes x and z separately: the plain `hash` is symmetric under negating two coordinates): `Kind` (Meadow, Woods, Peak (central mountain), Mushroom, Volcano (crater of lava, radial lava streaks), Frost (snow, ice floes on the sea around), Dunes (all sand)), cold and warm regions by a coarse climate noise (frost / sand and volcanoes), radius 10–66, `beach`, `wood`, `summit`. `rise(seed, x, z)` is the island's surface height (coast warped by noise, shelf sinking below the sea outside), `inward` (1 centre, 0 coast), `floe`, `streak`. `stone` is the waystone (flattest spot of a few candidates), `arrival` beside it facing it (`FACING_STONE`), `name` from syllables and a kind-flavoured title. The home island (cell 0, 0) is a meadow.
- `generate.rs` — `height(seed, x, z)` (ocean floor or the highest island `rise`), `column` (cover per island kind: grass/sand/clay/gravel/snow/stone/mycelium/basalt/lava, a `pool` of water at `SEA` or lava in a crater, `ice`), `chunk(seed, key)` (bedrock, caves as interpolated 3D noise on a 4-block grid, ore `veins` seeded per neighbouring chunk so they cross borders, `growth` seeded per column within `TREE_REACH`: oak, birch, spruce, palm trees and red and brown giant mushrooms by island kind, `bloom` scatters flowers in same-kind patches (meadows thickest), saplings and small mushrooms in woods, small mushrooms on mycelium, a few spruce and palm saplings on snow and sand; then each island's waystone: two `Waystone` blocks on a 5×5 cobblestone pad, stone below, air above), `spawn_point` (the home waystone). Pure: clients generate the same world from the seed, the server only sends edits. `cargo test --features dev map -- --ignored` writes a top-down `screenshots/map.ppm` (1280 blocks, waystones magenta) in ~1 s.
- `voxels.rs` — `Voxels` resource: `chunks` (32³ `Chunk`, `Uniform` or `Mixed`, `Arc` so meshing tasks can share them), `edits` (overlay applied on every `insert`, the source of truth that is networked), `dirty` chunk keys to remesh, `set`, `ensure` (generate synchronously, server side), `cast` (voxel DDA). World is 8 chunks tall (y 0..256), bedrock below, air above.
- `model.rs` — sub-block models made of texel-sized boxes: `bits(block)` (`Bit { low, high, color, tile }` on a 16-texel grid: `bit` tints the greyscale `Tile::Grain`, `skin` uses a block texture such as bark or a cap) for each flower, sapling and small mushroom; `icon` projects one onto its hotbar tile. `mesh::build` emits every box's six faces into the solid mesh, each face sampling its tile at the texels it covers (so models carry the textures' variation), tinted through the vertex colour, jittered by up to 2 texels per position.
- `texture.rs` — 16 px pixel-art tiles, hand-drawn: `Art` (16 strings of palette shades `0`–`3`, `.` = see through) coloured by a `Palette`, several tiles share one drawing (`drawn`, `solid`, `cutout`, `fringed` grass/snow/mycelium over dirt, `ore` spots over stone); planks, bricks, glass, lamp, basalt, waystones are geometric. No per-pixel noise: it reads as static. `paint(tile, x, y) -> Texel { color, glow }` into an 8×6 atlas with a hand-built mip chain (tiles stay aligned down to 1 px, so no bleeding), nearest sampling; `albedo()` and `glow()` (emissive) atlases, `uv_corner`. `cargo test --features dev atlas -- --ignored` writes `screenshots/atlas.ppm` (4× zoom).
- `mesh.rs` — `Padded::gather` copies a chunk plus a 1-block border from its 26 neighbours, `build` emits culled faces (no greedy meshing: the atlas can't repeat) with per-vertex ambient occlusion (quad flipped against anisotropy) times a sky term (depth below the generated surface, so caves go dark), split into `solid` (alpha-masked) and `liquid` meshes; water tops are lowered; logs are octagonal prisms (`OCTAGON`, corners cut by `CUT`; they don't hide neighbours' faces; their straight sides hide against opaque neighbours, tops and bottoms against logs too; `Builder::polygon` fans convex faces); water is opaque and glossy, its vertex colour tinted by the depth to the generated floor (`SHALLOWS` turquoise to `OPEN_SEA`).
- `stream.rs` — client chunk streaming around the `Pilot`: generation and meshing in `AsyncComputeTaskPool` tasks, nearest first, a few in flight (fewer on wasm); chunks beyond `reach + KEEP_BEYOND` dropped (edits survive); `Palette` materials; `Progress.pending` (screenshots wait for 0).
- `protocol.rs` — everything both ends register in the same order: replicated `Player { name }`, `Avatar { at, yaw, pitch }`, `Inventory` (hotbar `Stack`s), `skin::Skin`, `Visited` (island cells whose waystone the player has right-clicked), `Hopper` (a mob's position); client messages `Hello { name, password }` (sign in, rename, change password or switch account), `Paint(Skin)`, `Moved`, `Dig`, `Put`, `Travel(cell)`, `Attune(at)`; server messages `Welcome { seed, edits }`, `Possess(Entity)` (mapped), `Altered`, `Verdict` (`Accepted { name }` / `Refused { reason }`), `Teleport(Avatar)`. `Role`, `authority`, `plays`.
- `skin.rs` — `Skin`: 64×32 palette indices (`PALETTE`, 32 colours) in the classic box-UV layout: `Part` (Head 8×8×8, Body 8×12×4, Arm and Leg 4×12×4 shared by both sides) with `faces()` (top, bottom, right, front, left, back rects; the figure faces −Z, its right is +X) and `mesh()` (UV-mapped cuboid, `PX` metres per pixel); `fresh(seed)` paints a random default (hair, face, shirt, trousers, shoes), `used(texel)`, `image(backdrop)` (nearest-sampled; backdrop checkers the unused texels for the editor).
- `account.rs` — server accounts: `Account { name, salt, hash, avatar, inventory, skin, visited }` (`keep` takes a player's `Kept` components) in `Accounts` (index = id), passwords as salted, stretched SHA-256 (`admits`, `lock`), names unique ignoring case (`named`, `tidy`).
- `authority.rs` — the server: founds the world (from the save if there is one), sends `Welcome` to each authorized client; `sign_in` answers each `Hello` with a `Verdict`: unknown name → new account and player; known name → password must match and the account must not be playing; while playing, a free name renames, the own name changes the password, another account's name and password switch to it. Players are `Controller { client, account }` (the host's own player too, via the same `Hello`), spawned from their account and `Possess`ed; `Paint` replaces a valid skin; on disconnect the player's avatar, inventory and skin go back into the account. It applies `Moved`, `attune`s a player to the island whose waystone they right-clicked (`Attune(at)`, within reach; `Visited`), answers `Travel` (visited island, standing by a waystone) by moving the avatar to the first free spot above the island's `arrival` and sending `Teleport`, validates `Dig` (a model on top of the dug block comes along) / `Put` (reach, inventory, not inside a player, models only on solid ground) and broadcasts `Altered`, or sends the true block back to the one client to undo its prediction.
- `save.rs` — world saving (authority only, when `opts().saved_at()` is set): `World { seed, edits, accounts, shroomlings }` as JSON (`load` at startup, a corrupt file panics rather than being overwritten), written to `<path>.new` then renamed, at most every 5 s while something changed and on exit (window closed, or SIGINT/SIGTERM caught by `ctrlc`); online players' state is folded into their accounts.
- `net.rs` — replicon messaging backend over WebSockets: one binary frame per message, first byte the channel. Server (native only): non-blocking `TcpListener`, handshakes on threads, a `Link` per `ConnectedClient`. Client: `tungstenite` natively (`ws://` only), `web_sys::WebSocket` in the browser; held as the non-send `Uplink`. Drives `ClientState`/`ServerState`.
- `player.rs` — client side of the local player: `Bulk` (AABB size, `PERSON`; `body`, `cells`, `slide` are shared with mobs), `Pilot` (client-authoritative position, sent as `Moved` at 20 Hz), fixed-step AABB physics against voxels (unloaded chunks are solid; frozen until the chunks around are loaded), swimming, mouse look (click to grab and go fullscreen, Esc to release), Shift sprints (Ctrl+W would close the browser tab), `Aim` (target, digging progress), dig (hold LMB) / place (RMB) with prediction for guests, hotbar `Selected` (1–9, wheel). `arrive` builds `Voxels` from `Welcome`. Input is ignored while the menu is open; look speed and inversion come from `Settings`.
- `figure.rs` — other players as blocky figures built from the shared `Kit` of part meshes and a per-player `Clad` (skin image + material, rewritten when `Skin` changes); `assemble` (also used by the editor preview) places head (turned by pitch around the neck), body, swinging arms and legs; smoothed toward `Avatar`; UI name tags projected over their heads.
- `local.rs` — browser-side helpers, no-ops natively: `recall`/`remember` (localStorage), `random_bytes` (crypto), `copy` (clipboard), `pasted` (text from paste events), `pointer_locked`.
- `identity.rs` — client `Identity`: `sent` credentials (remembered in localStorage as `bloxy.identity` once accepted; first visit invents `WandererNNNN` and a `xxxx-xxxx-xxxx` password; natively `name`/`password` opts, password default empty), editable `fields`, `owed` (send `Hello` once `Voxels` exist), `standing`. A refusal before spawning opens the Profile tab.
- `settings.rs` — `Settings { reach, sensitivity, fov, invert }` (localStorage `bloxy.settings`, ignored in shot mode), `Knob`s with `turn`/`reading`; `apply` updates the camera's field of view and fog.
- `menu.rs` — Tab/Esc menu (also opens when the browser drops pointer lock): `Menu { open, tab, since }` (the cursor follows `open` whoever changes it), tabs `Settings`, `Profile` (name and password fields typed via `KeyboardInput` and paste, New password, Copy (browser), Save → `Identity::submit`), `Skin` (`editor::page`), `Waystones` (`waystone::page`). Buttons carry an `Act`; `click` turns presses into `Pressed(Act)` messages that `obey` (here and in the editor) handles.
- `editor.rs` — skin editor: `Draft` (skin, colour, `touched`; follows your worn skin until edited), canvas `ImageNode` (8 px per texel, `RelativeCursorPosition`; left paints, right picks), 32 swatches, Random / Undo all / Wear (`Paint`), and a turntable preview rendered by its own camera into an image on render layer 3.
- `waystone.rs` — client side of travel: the Waystones page lists `Visited` islands (name, kind, distance, heading) as `Act::Travel` buttons, rebuilt when the labels change; pressing one beside a waystone sends `Travel`; `arrive` applies `Teleport` to the `Pilot` and closes the menu. Right-clicking a `Waystone` block (`player::work`) sends `Attune` and opens the page.
- `shroomling.rs` — mushroom-man mobs on mushroom islands. Server (`authority`): `muster` spawns a colony (`3 + radius / 8`, replicated `protocol::Hopper { at, yaw, aloft }` + server `Wander`) once, when a player first comes within `WAKE` of a mushroom island's centre (`Colonies`); they are never despawned and are saved with the world (`World::shroomlings`, `lodge`); `wander` only moves those with a player within `SLEEP`, ensures the chunks around each, walks, rests and turns at random, turns back at drops and water and toward home past 0.8 radius, hops now and then and leaps when blocked (`player::slide` with its own `Bulk`). Client (`plays`): `Mold` (box meshes UV-mapped to a tiny painted sprite: spotted red cap, gills, pale body with eyes), `dress` adds them to each `Hopper`, `animate` smooths, swings the feet and stretches the body while aloft.
- `hud.rs` — crosshair, digging progress bar, hotbar with atlas icons and counts, status line (role/connection, players, position, target, fps, chunks loading), block outline.
- `sky.rs` — physical atmosphere, sun with cascaded shadows, `lens()` (exposure, ACES, bloom, distance fog that hides the streaming edge).

# Opts
Natively the env var `BLOXY` holds JSON5 `opts::Opts`; in the browser the URL query (`?connect=wss://host:port&name=Ann`, or `?opts={…}` for anything else). `connect` defaults to the build-time env var `BLOXY_CONNECT` (the Pages build sets the hosted server); `?connect=` (empty) plays solo. Fields: `connect` (server URL: guest), `serve: port` (headless dedicated server), `host: port` (play and serve), `name`, `password`, `menu: 'settings'|'profile'|'skin'|'waystones'` (start with the menu open; screenshots then don't wait for a player), `save` (world file; dedicated servers default to `world.json` in the working directory, other roles don't save unless given), `seed` (1), `reach` (view radius in chunks; 9 native, 6 web), `hour` (10), `creative` (starter hotbar with stacks of building blocks, fast digging), `shot: <secs>` (screenshot to `screenshots/shot-$SHOT_NAME.png` once loaded, then exit), `at: [dx, dz]` (spawn offset from the spawn point, on the ground), `yaw`, `pitch` (degrees), `press: [[secs, 'LMB'|'RMB'|'W'|'A'|'S'|'D'|'Space'|'Ctrl'|'Shift'|'Tab'|'Esc'|'1'…'9'], …]` (taps of 0.15 s), `hold: [[from, to, key], …]`.
e.g. `BLOXY='{shot: 2, yaw: 40, pitch: -15}' SHOT_NAME=valley tools/shot`. Screenshots are the way to check visuals — always look at them.

# Multiplayer
- Dedicated server: `BLOXY='{serve: 7777}' cargo run --features dev`. Browser pages served over https (GitHub Pages) can only open `wss://`, so put the server behind a TLS proxy (e.g. Caddy `reverse_proxy localhost:7777`) and join with `?connect=wss://your.host`. Native clients use `ws://host:7777`.
- Hosting: `.github/workflows/server.yml` builds the server on GitHub Actions (`--profile server`: release without LTO, stripped) on pushes to `master` or the working branch, verifies the host key fingerprint, uploads the binary to `/opt/bloxy/bin/bloxy` as the `bloxy` user (secret `DEPLOY_KEY`) and waits for the `bloxy-restart.path` unit to restart the service. `deploy/setup.sh` is the one-time root bootstrap of the Debian host: ufw (22, 80, 443, 7777), the `bloxy` user and its deploy key (printed for the secret), the `bloxy` service (`serve: 7777`, working dir `/opt/bloxy/world`) and Caddy terminating TLS for `wss://$DOMAIN`. Cloud sessions can't SSH out.
- `tools/duo` runs a dedicated server and two clients under xvfb and screenshots the second seeing the first: the quickest end-to-end check of netcode.
- Movement is client-authoritative; blocks, inventories and player list are server-authoritative.
- The hosted world lives in `/opt/bloxy/world/world.json` (edits and accounts); delete it (service stopped) to start a fresh world (needed when generation changes, or old edits land on new terrain). The browser's solo mode doesn't save.
- The UI font has no `−`, `×`, `°` or `…` glyphs: use ASCII.

# Build
Priority is fast incremental builds over runtime speed. Debug builds only; release only when asked.
- `cargo check` to verify compilation; `cargo run --features dev` to play (`dev` = Bevy dynamic linking).
- `tools/shot <name> '<opts>'` builds and screenshots under xvfb.
- Cloud sessions have no GPU: wrap runs in `xvfb-run -a -s "-screen 0 1600x900x24"` (lavapipe, software Vulkan, slow frames).
- Bevy runs without default features: `Cargo.toml` lists only what the game uses. Add a feature there when using a new Bevy part.
- Web build: `trunk build --release` (`index.html`), deployed to GitHub Pages (`.github/workflows/pages.yml`, Settings → Pages → Source: GitHub Actions) on pushes to `master` or the working branch, joining the hosted server by default. Needs WebGPU.
- On a panic or startup failure (including Bevy system param conflicts), rerun with `RUST_BACKTRACE=1`.
- Docs: https://docs.rs/bevy/0.19.1/bevy/ , https://docs.rs/bevy_replicon/0.44.3/bevy_replicon/

# Style
Code structure should mirror the thinking behind it: translate the user's conceptual framework fairly directly into code. Functional-ish.
- Format with `cargo +nightly fmt` (repo `rustfmt.toml` uses nightly-only options). Avoid comments; name things well.
- Order within a file: if A refers to B, A comes after B. Keep related code together.
- Semicolons are a verbosity signal: prefer expressions over statements.
- No `return`, `continue`, `let … else`, or early exits.
- Prefer let chains over nested `if let`/`if` or `.and_then()`.
- Prefer `Option` methods over matching on `Option` (not so for most other enums).
- Prefer `find`, `find_map`, `any`, `fold` over loops with break (socket read loops are the exception).
- Eagerly destructure: `let &Thing { field } = thing()`.
- Domain model with named instances, newtypes and associated consts.
- No more function-calls-function indirection than needed.
- ECS: merge components that always co-occur. Name components by behaviour, not entity.
