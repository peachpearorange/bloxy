# Bloxy
A browser-first multiplayer voxel sandbox in Bevy 0.19.1, aiming at the feel of big modded block-building packs: a procedural ocean of diverse islands with ores, caves and trees, waystones to travel between them, mining and building, other players around you, and (later) machines, power and automation. Everything is procedural: no mesh or texture assets.

# Roles
`protocol::Role` (from opts): `Solo` (no network, local authority), `Host` (native window + WebSocket server), `Dedicated` (headless server, `MinimalPlugins`), `Guest` (connects to a server; the browser build is usually this or `Solo`). `authority` systems run for every role but `Guest`; `plays` systems for every role but `Dedicated`. Use these, not replicon's states, to gate game logic: replicon's `ClientState::Disconnected` also covers a guest that lost its connection.

# Modules
- `block.rs` — `Block` (u8 repr, append new variants so saves and the wire keep their meaning; `look` → `Opaque/Cutout/Liquid/Invisible/Model/Log`, `leafy`, `modelled` (flowers, saplings, small mushrooms: `Poppy` to `BrownMushroom`, `ALL_MODELS`, `TallGrass`, `Torch`, ladders and beds; not solid but targetable, plants break at once), `LADDERS` (`Ladder` hangs on the -Z wall, `LadderEast/South/West` the other walls; `wall`, `against(wall)` picks the variant when placing, `held` maps every variant back to the `Ladder` or `Bed` item), `BEDS` (2×1 beds: a foot and a head half for each direction the head lies; `laid(toward)`, `partner` points at the other half, `pillow` marks heads), `liquid` → `(Fluid, level)` (`Fluid::Water`/`Lava` sources are level 0, `WaterFlow1..7` / `LavaFlow1..3` the flowing levels; `Fluid::flowing(level)`, `reach`, `delay`), `fluid` (swum in, not solid), `waystone` (`Waystone` base and `WaystoneTop`, solid pedestal models), `station` (`CraftingTable`, `Furnace`), `sign` (`SIGNS`: each log with its sign: Oak, Birch, Spruce, Palm; modelled, drawn by `sign.rs` instead of the chunk mesh), `plant` (the jittered models), `item`, `tool` (`Boat`, `Bucket`, `WaterBucket`, `LavaBucket`, `Feather`, `FishingRod`, `Charcoal`, the `FISH` (Cod, Salmon, TropicalFish, Pufferfish): items only, not `placeable`), `stack` (most 64, buckets 16, filled buckets, boats, rods and beds 1), `carrying` (a filled bucket's `Fluid`; `Fluid::bucket`, `source`), `solid`, `breakable` (not bedrock or waystones), `ROCKS` (each stone with the cobblestone it drops: Stone, Granite, Diorite, Andesite, Limestone, Slate), `rock`, `seconds_to_break`, `drop`, `tiles` = top/side/bottom `Tile`s). Add a block: variant + every match, and a `Tile` with its `paint`.
- `noise.rs` — integer-hash value noise and Perlin (`perlin2`, `perlin3`, `fbm2`, `unit`, `hash`). Only `+ - * floor` and integer ops, so wasm and native generate bit-identical worlds; never use `sin`/`exp`/`powf` in anything that feeds generation.
- `island.rs` — the archipelago: one `Island` (or none, 8%) per `CELL` (128 blocks) square, centre jittered, cached by `Island::at(seed, cell)` (`within(low, high)`, `near(at)`, `beside(at)` = the island whose waystone is within reach). Random per cell (`key` hashes x and z separately: the plain `hash` is symmetric under negating two coordinates): `Kind` (Meadow, Woods, Peak (central mountain), Mushroom, Volcano (crater of lava, radial lava streaks), Frost (snow, ice floes on the sea around), Dunes (all sand)), cold and warm regions by a coarse climate noise (frost / sand and volcanoes), radius 10–66, `beach`, `wood`, `summit`. `rise(seed, x, z)` is the island's surface height (coast warped by noise, shelf sinking below the sea outside), `inward` (1 centre, 0 coast), `floe`, `streak`. `stone` is the waystone (flattest spot of a few candidates), `arrival` beside it facing it (`FACING_STONE`), `name` from syllables and a kind-flavoured title. The home island (cell 0, 0) is a meadow.
- `generate.rs` — `height(seed, x, z)` (ocean floor or the highest island `rise`), `column` (cover per island kind: grass/sand/clay/gravel/snow/stone/mycelium/basalt/lava, a `pool` of water at `SEA` or lava in a crater, `ice`), `chunk(seed, key)` (bedrock, caves as interpolated 3D noise on a 4-block grid, geology (`rock`: stone is folded sedimentary `Strata` (a 1D noise of height + `fold`, drifting between regions) of stone, limestone, andesite and thin slate seams, over a wavy slate `basement`, cut by granite or diorite plutons (`intrusion`, 3D noise on the cave grid, commoner deeper; the `magma` kind is regional), andesite through volcano islands), ore `veins` seeded per neighbouring chunk so they cross borders (replacing any rock), `growth` seeded per column within `TREE_REACH`: oak (2-3 branches toward `COMPASS` points, each ending in a ragged leaf `clump`, plus one on top), birch (one tall ragged ellipsoid), spruce (tiers with nibbled rims), palm trees and red and brown giant mushrooms by island kind, `bloom` scatters flowers in same-kind patches (meadows thickest), tall grass in noisy swards on grass, saplings and small mushrooms in woods, small mushrooms on mycelium, a few spruce and palm saplings on snow and sand; then each island's waystone: two `Waystone` blocks on a 5×5 cobblestone pad, stone below, air above), `spawn_point` (the home waystone), `overview(seed, x, z)` (visible top block, its height and the ground under any water, for maps), `GENERATION` (bump whenever generation changes: a save from another generation keeps only its claimed chunks). Pure: clients generate the same world from the seed, the server only sends edits. `cargo test --features dev map -- --ignored` writes a top-down `screenshots/map.ppm` (1280 blocks, waystones magenta) in ~1 s; `cargo test --features dev section -- --ignored` writes a vertical slice (768 x 160) to `screenshots/section.ppm`.
- `voxels.rs` — `Voxels` resource: `chunks` (32³ `Chunk`, `Uniform` or `Mixed`, `Arc` so meshing tasks can share them), `edits` (overlay applied on every `insert`, the source of truth that is networked), `kept` (whole chunk columns (`COLUMN` blocks) that replace generation: claimed land kept through a regen; `generated(seed, kept, key)` is what every chunk is built from, `snapshot(column)`, `pack`/`unpack` deflate them), `touched` (columns edited since the claims last refreshed their snapshots), `dirty` chunk keys to remesh, `set`, `ensure` (generate synchronously, server side), `cast` (voxel DDA; `cast_for` with another block predicate, e.g. to hit fluids). World is 8 chunks tall (y 0..256), bedrock below, air above.
- `model.rs` — sub-block models made of texel-sized boxes: `bits(block)` (`Bit { low, high, color, tile }` on a 16-texel grid: `bit` tints the greyscale `Tile::Grain`, `skin` uses a block texture such as bark or a cap) for each flower, sapling, small mushroom and tall grass (thin blades), the torch, the ladder (rails and rungs; `turned` by quarter turns for the other walls), the bed halves (foot: legs, mattress, blanket; head: headboard, pillow; `turned` like ladders) and the two waystone halves (stepped plinth, rune pillar, flared capital); `icon` projects one onto its hotbar tile. `mesh::build` emits every box's six faces into the solid mesh, each face sampling its tile at the texels it covers (so models carry the textures' variation), tinted through the vertex colour, plants jittered by up to 2 texels per position (`shift(block, seed, at)`); `bounds` is a model's tight box in the world (signs: a fixed narrow box around the post and the middle of the board), also its hitbox (`voxels::cast` skips a model cell the ray misses).
- `texture.rs` — 16 px pixel-art tiles, hand-drawn: `Art` (16 strings of palette shades `0`–`3`, `.` = see through) coloured by a `Palette`, several tiles share one drawing (`drawn`, `solid`, `cutout`, `ore` spots over stone); grass and mycelium tops are `turf` (lattice clouds with staggered blade strokes), `fringed` sides hang ragged turf (2–6 px per column, shadowed edge) over `soil` (dirt, flecked like stone); buckets are one drawing whose inner rim row takes the fluid's colour; planks, bricks, glass, lamp, basalt, waystones are geometric; the rock varieties are the stone and cobblestone drawings in `shades` of each `rock` colour. Stone is `smooth` (periodic `lattice` value noise ramped through the palette, the drawing's flecks on top); cobblestones are `cobble`: six round pebbles found by flood fill in the drawing (`PEBBLES_OF_COBBLE`), barely tinted greys shaded as domes lit from the top left (`DOMES_OF_COBBLE`: each texel's offset from its pebble's centre), dark mortar, hairline cracks (`CRACKS_OF_COBBLE`) wandering in from the edge of about half the larger pebbles; wool is curly lattice noise; feather, fishing rod and fish (`fish` palettes over one drawing, the pufferfish its own) are cutout drawings. `paint(tile, x, y) -> Texel { color, glow }` into an 8×12 atlas with a hand-built mip chain (tiles stay aligned down to 1 px, so no bleeding), nearest sampling; `albedo()` and `glow()` (emissive) atlases, `uv_corner`; `icons()` is the UI icon atlas (`ICON` = 32 px cells, `ICON_COLUMNS`, indexed by `Block` value): opaque, cutout and log blocks as isometric cubes (top and side tiles, sides shaded), everything else its side tile; `timber(sign)` is a sign's wood palette; the water tile is only drawn for icons and maps (the world's water is `water.rs`'s shader). `cargo test --features dev atlas -- --ignored` writes `screenshots/atlas.ppm` (4× zoom).
- `mesh.rs` — `lone(block, at, seed, torches)` meshes one block alone as triangles of `Corner`s (the crumble shell). `Padded::gather` copies a chunk plus a 1-block border from its 26 neighbours, `build` emits culled faces (no greedy meshing: the atlas can't repeat) with per-vertex ambient occlusion (quad flipped against anisotropy) times a sky term (depth below the generated surface, so caves go dark), split into `solid` (alpha-masked) and `liquid` meshes; fluid tops are lowered by level (`crest`; full height under the same fluid), sides step down against lower levels, lava goes into the solid (emissive) mesh; torchlight (`TORCH_REACH` 14 blocks, slightly warm, from `Voxels::torches_near` = torch edits around the chunk, no occlusion) is baked into vertex colours as max(sky, torch); grass faces are tinted by `meadow` (world-space fbm between `DRY` and `LUSH`) so lawns don't tile; logs are octagonal prisms (`OCTAGON`, corners cut by `CUT`; they don't hide neighbours' faces; their straight sides hide against opaque neighbours, tops and bottoms against logs too; `Builder::polygon` fans convex faces); water is opaque and glossy, its vertex colour tinted by the depth to the generated floor (`SHALLOWS` turquoise to `OPEN_SEA`).
- `stream.rs` — client chunk streaming around the `Pilot`: generation and meshing in `AsyncComputeTaskPool` tasks, nearest first, a few in flight (fewer on wasm, where at most one of each starts per frame since tasks run on the main thread); chunks beyond `reach + KEEP_BEYOND` dropped (edits survive), meshes beyond `reach` despawned and their chunks marked dirty again so they are remeshed on the way back; `Palette` materials (`liquid` is the `water::Water` shader); `Progress.pending` (screenshots wait for 0).
- `protocol.rs` — everything both ends register in the same order: replicated `Player { name, hue }` (`HUES`: 16 player colours, `hue(index)`; client message `Tint(index)`), `Avatar { at, yaw, pitch, held }` (`held`: the selected item, shown in their hand), `Inventory` (`SLOTS` = 9 hotbar + 27 backpack `Stack`s plus the `CURSOR` slot (the stack carried by the mouse in the inventory, outside `count`/`add`/`take`); old saves are padded; `count`, `shuffle` moves, merges or swaps, `halve` takes half a stack onto the cursor, `drop_one` puts one from it, `stow` puts it back; client message `Picked(Pick::Half | One | Stow)`), `skin::Skin`, `Visited` (island cells whose waystone the player has right-clicked), `Bookmarks` (JEI bookmarks, toggled by the client message `Mark(Block)`), `Hopper` (a mob's position); chat: client `Say(text)` (at most `LONGEST_SAYING`), server `Said { name, hue, text }` to everyone; client messages `Hello { name, password }` (sign in, rename, change password or switch account), `Paint(Skin)`, `Moved`, `Dig`, `Put`, `Travel(cell)`, `Attune(at)`, `Shuffle { from, to }`, `Craft(recipe index)`, `Scoop(at)` / `Pour { at, fluid }` (buckets), boats (`Launch(water cell)`, `Board(Entity)`, `Wreck(Entity)` mapped, `Disembark`, `Steer { at, yaw }` unreliable); replicated `Vessel { at, yaw, rider }`, `Sign { at, yaw, wood, text }` (client message `Inscribe { at, text }`), `Beast { breed: Sheep(Fleece) | Lizard, at, yaw, pose }`, `Ship { band, at, yaw, aim }`, `Folk { band: Trader | Pirate | Viking, at, yaw, luck, blows, aboard }`, `Health` (players, folk, beasts and birds, `FULL` = 20), `Cannonball`, `Loose { block, count, at }` (an item lying in the world; client message `Toss { slot, all }`), server message `Knock(push)` (a blow's knockback added to the `Pilot`'s velocity); client messages `Strike(Entity)` (punch a hostile) and `Trade { trader, offer }`, both mapped; server messages `Welcome { seed, edits, kept }`, `Possess(Entity)` (mapped), `Altered`, `Notice(text)`, client `Rest(at)` (right-click a bed: sets the player's `Bedside`, kept in the account, where `folk::perish` revives them while the bed stands), `Verdict` (`Accepted { name }` / `Refused { reason }`), `Teleport(Avatar)`. `Role`, `authority`, `plays`.
- `recipe.rs` — shapeless crafting (torches from planks and coal or charcoal, charcoal smelted from 2 logs without fuel, ladders from planks, a bed from planks and wool or feathers, a fishing rod from planks and wool): `Recipe { inputs, output, station }` built by `hand`, `table` (needs a `CraftingTable` within reach) or `furnace` (smelting with coal as fuel: stones from cobblestones, glass, bricks, a bucket from 3 iron ore) in `RECIPES`; `missing(inventory)`, `housed(stations)`, `ready`, `made(inventory, stations)` (the inventory after crafting, if the inputs and station are there and the output fits), `making`/`using(block)` (a station is 'used' by its recipes), `craftable`.
- `sign.rs` — signs: placing a sign block makes the server spawn a replicated `Sign` turned toward the placer in 16 steps (`facing`), saved with the world, despawned when its block is gone (`topple`); `Inscribe` sets its text (`tidy`: `LINES` lines of `LINE` characters). Clients draw a post and board whose texture (`engrave`) is the wood's grain with the text in a 3×5 pixel font (`GLYPHS`, centred lines, unknown characters as `?`). Placing or right-clicking a sign opens the Sign tab (`Inscription`: four `menu::Entry::Line` fields, Enter moves down); closing the menu sends the text (`seal`).
- `beast.rs` — animals. Punching a beast (`shear`) hurts it (`Health`: sheep 8, lizards 6), knocks it back (`stagger`) and makes it flee (`Mood::Dash`); a struck lizard holds a `GRUDGE`: it hunts the nearest player within `CHASE` (`Mood::Hunt`) and bites within `JAWS` (`BITE`, knockback, every `BITE_EVERY`); a sheep also gives a `Wool` block (again after `REGROW`) and drops wool when killed (`loose::scatter`). Server: `muster` stocks each island once when a player comes within `WAKE` (`Herds`): sheep on meadows and woods (fleece colours by chance), water lizards in the shallows around most islands; `roam` (watched ones only) runs a `Mood` per beast: sheep idle, graze and stroll, avoiding water and drops, staying home; lizards swim near the coast, head for land (`seek`), stroll and dash on two legs ashore (and flee players within `SKITTISH`), then run back to the water; swimming floats at the surface, a blocked beast leaps (`LEAP` clears a block, out of the water too). Client: `Shapes` caches cuboid meshes and colour materials (`Grain`: plain, wool, scales textures); `rig` spawns a hierarchy of `Bone`s with `Joint` markers (`Rest` pivot) and `animate` poses them from `Pose` and the measured pace (`stance`): grazing heads, leg swings, the lizard's upright walk and goofy leaning run with whirling legs, flailing arms and a wagging tail, horizontal swimming.
- `folk.rs` — people: `Band` health/speed/blow; `struck` (ray vs a person's box). Players carry `Health` and `Vigour` (mending after `MEND_AFTER` s, 1 point per `MEND_EVERY`); at 0 they are revived at the home waystone (`perish`, `Teleport`, off any boat). `Raider`s (crews put ashore) chase the nearest player within `CHASE`, swim, scramble up to 2 blocks, sidestep when stuck (`detour`), strike in reach (`blows` counts swings for the animation; each blow sends the player a `Knock`, as do cannonball blasts) and give up after `GIVE_UP` s alone. `strike` applies a player's punch (`PUNCH`, knockback). Client: `outfit` paints a skin per band (striped shirts, bandanas, beards, robes), `dress` builds the figure from `figure::Kit` with hats, a cutlass or axe and a viking shield, `animate` walks, chops, brandishes weapons aboard and flushes red when hurt; `fight` sends `Strike` on left click at a hostile.
- `ship.rs` — ships: `Tides` schedules a trader passing a random player (from `opts.trader` s, then every 100–200 s, course found by `passage` over deep water) and a raid on a random player ashore (from `opts.raid`, then every 6–10 min; `approach` picks the nearest coast and a start 60 blocks out). `launch` spawns a `Ship` with its `Voyage` and a seated `Crew` of `Folk` (`ferry` keeps them on deck). `sail` steers around shallows (probes ahead), traders hold still near a player (`LINGER`), raiders run aground near the landing, throw the crew overboard as `Raider`s and leave once all are gone; pirate ships fire `Cannonball`s (ballistic, `fly`, blast damage within `BLAST`) at players within `CANNON_RANGE`. Ships vanish beyond `VANISH`. Client: `rig` builds the planked hull (`boat::planked`, tinted) with mast, yard, sail (`canvas`: cream, skull and crossbones, red and white stripes), viking shields and dragon prow, the pirate cannon (turned by `aim`); `bob` rocks them; cannonballs burst into a fading `Blast`.
- `trade.rs` — trading: `offers(luck)` picks 4 of `OFFERS` per trader; right-clicking a trader (`hail`) opens the Trade tab listing them (have counts, Trade buttons, rebuilt when the counts change); the server checks reach and `barter`s.
- `flow.rs` — fluid simulation on the authority: `Flows::stir(at, when)` queues a cell and its neighbours (dig and put stir; changes stir again after `Fluid::delay`: water 0.25 s, lava 1 s); `next` is a cell's new state: sources stay (lava touching water turns to basalt), fluid falls (level 1 under any fluid), spreads sideways from cells that can't fall up to `reach`, dries without a feed, and a new flow touching the other fluid becomes cobblestone; plants are washed away and drop as floating items. At most `PER_FRAME` cells a frame, each change broadcast as `Altered`.
- `boat.rs` — boats: right-click water with a Boat to `Launch`, right-click a boat to `Board`, left-click an empty one to `Wreck` it back into the inventory, Shift leaves. The rider steers client-side (`player::Riding`: A/D turn, W/S row, floats at the water surface, `slide` against blocks, crawls on land) and sends `Steer`; the server keeps `Vessel`s (saved as `World::boats`, rider cleared when the player leaves). `struck` is the ray test against the rotated hull (`player::work` lets a boat in front block block-targeting); `moor` gives each vessel the plank hull mesh.
- `hand.rs` — the first-person arm: the player's skin on the `Kit` arm, child of the camera, swinging when clicking or digging and swaying with `player::Gait`; a `Grip` at the end of an arm (this one, marked `Fist`, and every figure's right arm, raised a little while holding) shows the held item (`loose::Looks` mesh: a small cube or the item's one-texel-thick cutout; in first person the cutout rises forward from the fist with its face turned up and a little away); while a fishing rod is selected a `Rod` (shaft, cork grip, reel) sways with it, its `RodTip` anchoring the fishing line.
- `minimap.rs` — top-right round map (pixels outside the circle are transparent, a dark `RING` around it): 128 x 128 blocks around the player at 1 px each, `ROWS_PER_FRAME` rows a frame from the loaded chunks (top visible block per column, colour = the block's averaged top tile, water by depth, relief from the northern neighbour), shifted when the player moves, redrawn every `REDRAW_EVERY` with visited waystones (magenta), other players (in their hue) and a red heading arrow; coordinates and the island's name below.
- `crafting.rs` — the Inventory tab (E), JEI-like, using the whole panel width: the player's `protocol::Bookmarks` at the far left (A over any item sends `Mark` to toggle one), in the middle the recipe panel for the `Chosen` item (Made from / Used in cards: ingredient icons with have/need counts, red when short, the station, a Missing line, Craft button when possible; icons are clickable) above the backpack and hotbar slots (left click `Shuffle`s between the slot and `CURSOR`: picks a stack up, puts it down, swapping with what was there; right click takes half a stack or, while carrying, puts one item; the carried stack's icon follows the mouse (`Carried`) and goes back into the inventory when the tab closes), at the far right a `menu::Search` field and every item (`Block::ALL` that are `item`s) filtered by name, craftable ones (with the `Nearby` stations) first with green borders; a `Tooltip` follows the cursor over items.
- `skin.rs` — `Skin`: 64×32 palette indices (`PALETTE`, 32 colours) in the classic box-UV layout: `Part` (Head 8×8×8, Body 8×12×4, Arm and Leg 4×12×4 shared by both sides) with `faces()` (top, bottom, right, front, left, back rects; the figure faces −Z, its right is +X) and `mesh()` (UV-mapped cuboid, `PX` metres per pixel); `fresh(seed)` paints a random default (hair, face, shirt, trousers, shoes), `used(texel)`, `image(backdrop)` (nearest-sampled; backdrop checkers the unused texels for the editor).
- `account.rs` — server accounts: `Account { name, salt, hash, avatar, inventory, skin, visited, bookmarks, bedside, hue }` (`hue()`: the chosen colour or one from the name) (`keep` takes a player's `Kept` components) in `Accounts` (index = id), passwords as salted, stretched SHA-256 (`admits`, `lock`), names unique ignoring case (`named`, `tidy`).
- `authority.rs` — the server: founds the world (from the save if there is one), sends `Welcome` to each authorized client; `sign_in` answers each `Hello` with a `Verdict`: unknown name → new account and player; known name → password must match and the account must not be playing; while playing, a free name renames, the own name changes the password, another account's name and password switch to it. Players are `Controller { client, account }` (the host's own player too, via the same `Hello`), spawned from their account and `Possess`ed; `Paint` replaces a valid skin; on disconnect the player's avatar, inventory and skin go back into the account. It applies `Moved`, `attune`s a player to the island whose waystone they right-clicked (`Attune(at)`, within reach; `Visited`), answers `Travel` (visited island, standing by a waystone) by moving the avatar to the first free spot above the island's `arrival` and sending `Teleport`, applies `Shuffle`, `Mark` and `Craft`, `scoop`s a fluid source into a bucket and `pour`s a filled one into an open cell (air, plant or flowing fluid; both stir the flows), (`Recipe::made` with the stations near the avatar), validates `Dig` (the block's `drop` and any model on top fall into the world as `Loose` items via `loose::fall`) / `Put` (reach, inventory, not inside a player, models only on solid ground) and broadcasts `Altered`, or sends the true block back to the one client to undo its prediction.
- `save.rs` — world saving (authority only, when `opts().saved_at()` is set): `World { seed, edits, accounts, shroomlings, boats, signs, claims, kept, generation }` (claims and kept columns as base64 of deflated columns) as JSON (`load` at startup, a corrupt file panics rather than being overwritten), written to `<path>.new` then renamed, at most every 5 s while something changed and on exit (window closed, or SIGINT/SIGTERM caught by `ctrlc`); online players' state is folded into their accounts.
- `net.rs` — replicon messaging backend over WebSockets: one binary frame per message, first byte the channel. Server (native only): non-blocking `TcpListener`, handshakes on threads, a `Link` per `ConnectedClient`. Client: `tungstenite` natively (`ws://` only), `web_sys::WebSocket` in the browser; held as the non-send `Uplink`. Drives `ClientState`/`ServerState`.
- `player.rs` — client side of the local player: `Bulk` (AABB size, `PERSON`; `body`, `cells`, `slide`, `march` (fixed-step move returning `Marched`) are shared with mobs), `Pilot` (client-authoritative position, sent as `Moved` at 20 Hz; `riding` a boat), fixed-step AABB physics against voxels (unloaded chunks are solid; frozen until the chunks around are loaded), swimming (pressing W or Space against a wall with the head out of the water `scrambling` leaps out: `JUMP` for `SCRAMBLE_FOR` s after leaving the water), climbing ladders (W or Space up, S down, slow slide otherwise), `Knock`s (`reel`: `staggered` for `STAGGER` s, barely steering), no walking or jumping while digging on the ground (in the air or water you keep moving), view bobbing (`Gait`: stride and sway, also used by the arm; the camera takes `BOB` of it), `View` (V toggles first person and `Behind`: the camera `BEHIND` m back, pulled in before walls, own figure shown by `figure::mirror`, arm hidden), mouse look (every left click goes fullscreen again, menu open or not, and grabs the pointer while playing; Esc to release), Shift sprints (Ctrl+W would close the browser tab), `Aim` (target, digging progress), dig (hold LMB) / place (RMB; right-clicking a waystone attunes, a crafting table or furnace opens the inventory; with an empty bucket a fluid source sends `Scoop`, with a filled one `Pour` goes into the fluid cell aimed at or beside the block aimed at) with prediction for guests, hotbar `Selected` (1–9, wheel). `arrive` builds `Voxels` from `Welcome`. Input is ignored while the menu is open; look speed and inversion come from `Settings`.
- `figure.rs` — other players as blocky figures built from the shared `Kit` of part meshes and a per-player `Clad` (skin image + material, rewritten when `Skin` changes); `assemble` places head (turned by pitch around the neck), body, swinging arms and legs; smoothed toward `Avatar`; a `plate` with the name in the player's hue floats over each head.
- `local.rs` — browser-side helpers, no-ops natively: `recall`/`remember` (localStorage), `random_bytes` (crypto), `copy` (clipboard), `pasted` (text from paste events), `pointer_locked`, `listen_for_clicks` + `capture_on_click` (every left mousedown re-requests fullscreen on the canvas inside the gesture, and pointer lock while playing, as either can be lost).
- `identity.rs` — client `Identity`: `sent` credentials (remembered in localStorage as `bloxy.identity` once accepted; first visit invents `WandererNNNN` and a `xxxx-xxxx-xxxx` password; natively `name`/`password` opts, password default empty), editable `fields`, `owed` (send `Hello` once `Voxels` exist), `standing`. A refusal before spawning opens the Profile tab.
- `settings.rs` — `Settings { reach, sensitivity, fov, invert }` (localStorage `bloxy.settings`, ignored in shot mode), `Knob`s with `turn`/`reading`; `apply` updates the camera's field of view and fog.
- `menu.rs` — Tab/Esc menu (also opens when the browser drops pointer lock): `Menu { open, tab, since, chatting }` (the cursor follows `open` whoever changes it), the whole screen dimmed, no panel or border, the pages filling it (the hotbar and status line hide meanwhile), tabs `Inventory` (`crafting::page`; E opens and closes it unless typing), `Settings`, the unlisted `Sign` and `Trade` (opened by right-clicking a sign or trader), `Profile` (name and password `field`s typed via `KeyboardInput` and paste, like the inventory's `Search`, New password, Copy (browser), Save → `Identity::submit`; 16 colour swatches (`Act::Hue` → `Tint`, the current one lit)), `Skin` (`editor::page`), `Waystones` (`waystone::page`). Buttons carry an `Act`; `click` turns presses into `Pressed(Act)` messages that `obey` (here and in the editor) handles.
- `editor.rs` — skin editor painted directly on the figure: `Draft` (skin, colour, `touched`; follows your worn skin until edited), the figure's six `Piece`s (head, body, both arms and legs on render layer 3) seen by an `Orbit` camera rendered into the `Easel` image; `brush` casts the cursor ray against the visible pieces' boxes (`struck`, `texel` maps the face point to the skin texel): left paints, left-drag beside the figure turns it, right-drag turns it too; right-click fades a piece to the translucent `ghost` material (`Ghostly`, skipped when painting) and again brings it back (Show all parts restores all), middle-click picks a colour, the wheel zooms; 32 swatches, Random / Undo all / Wear (`Paint`).
- `waystone.rs` — client side of travel: the Waystones page lists `Visited` islands (name, kind, distance, heading) as `Act::Travel` buttons, rebuilt when the labels change; pressing one beside a waystone sends `Travel`; `arrive` applies `Teleport` to the `Pilot` and closes the menu. Right-clicking a `Waystone` block (`player::work`) sends `Attune` and opens the page.
- `claim.rs` — land claims: each player may claim `MOST` (20) chunk columns (32 × 32, full height) by clicking them on the map (`Stake(column)` toggles: claim a free one, release your own). Replicated `Claim { column, owner, hue }` (owner names and colours follow the player) with server-side `Holding { account, snapshot }`; `barred` refuses others' digging, placing, scooping and pouring there (`authority::guarded` sends the `Notice`). `refresh` re-snapshots (`Voxels::snapshot`, packed) claimed columns that were edited, every 5 s while saving, so the save always holds their current blocks (`Deed`s). `regen(world, seed)` (admin) snapshots every claimed column into `Voxels::kept`, drops all other edits, clears and restocks mobs, re-`Welcome`s every client (and moves players to the new spawn when the seed changes). Loading a save whose `generation` differs from `GENERATION` does the same from the saved snapshots.
- `chart.rs` — the Map tab (M, or the Map button): an image as large as its node (`fit`) of the generated world (`generate::overview` coloured like the minimap, water by depth, relief), cached as `TILE`² pixel tiles per zoom (`sample`, nearest the view centre first within `BUDGET` a frame, at most `KEPT_TILES`), so panning only blits cached tiles, at `SCALES` from 4 px per block to 32 blocks per px; the wheel zooms about the cursor, dragging pans, a click claims or releases the chunk under it. Over it: claims (in their owner's hue), the chunk grid when zoomed in, visited waystones, players and your arrow; the line below shows the cursor's coordinates, chunk and owner, and your claim count.
- `fx.rs` — `bevy_hanabi` particles (`Effects`, a soft `dot` texture): particles face the camera plane: a few rising embers on every lit torch (`sky::kindle` attaches them) and slow cyan-violet motes swirling up around each waystone within `ENCHANTED` (`Glimmers`).
- `admin.rs` — native authority only (serve/host, or the `admin` opt): a text command port on 127.0.0.1 (`admin` opt, default `PORT` 7778), one command per connection, answered from the ECS by the exclusive `obey`: `players`, `get`/`set`/`fill`, `column`, `top`/`layer` (text maps with legends), `image` (top-down PNG of the surface with players, mobs and claim edges), `mobs`, `spawn`, `kill`, `claims`, `regen [seed]`; `help` lists them. Clients: `bloxy admin <command ...>` (the same binary) or `tools/bloxyctl <command ...>`.
- `fishing.rs` — right-click water with a `FishingRod` (`CAST_REACH`) sends `Cast`; the server rolls the `catch` (cod; salmon in cold, tropical fish in warm water; pufferfish; treasure ores, more on the open sea; junk logs and buckets), keeps a `Line` and answers `Bite { catch, after }`. The client floats a bobber on a line from the rod tip, dips it when the fish bites (`Notice`), and a right-click within `HOOK_WINDOW` starts the `Fight`: hold RMB to lift the green zone in the bar and keep the fish (its icon, darting by its `Temper`) inside to fill the gauge; full sends `Reel(true)` (the server adds the catch if the bite was due), empty or walking off (`SNAP`) `Reel(false)`.
- `weather.rs` — replicated `Weather { sky: Clear | Cloudy | Rain | Storm }`, turned by the authority after spells of 90-240 s (`weather` opt pins it). Clients ease a `Climate` (cloud cover, wetness, sunlight) toward the sky: volumetric clouds (`Cloud` material, `cloud.wgsl`, embedded): a `CLOUD_THICK` slab box drawn by its back faces around the player, each pixel raymarches the slab (20 steps): a 2D coverage map (warped cells + fbm, offset by cover) gives each column's height, 3D value noise erodes the edges, three samples toward the light shade it, distance fades it into haze, `DROPS` rain streaks (snow flakes on frost islands or high up) falling in a box around the eye down to each column's top block, dimmer sun and denser, greyer fog, and lightning bolts with a flash in storms.
- `bird.rs` — replicated `Bird { breed: Swan | Raven | Gull | Parrot, at, yaw, stance }`. Server: `muster` settles flocks on each island once a player comes within `WAKE` (swans on meadow and woods water, ravens on woods, peaks, frost, volcanoes and mushrooms, gulls on coasts, parrots on palm islands); `fly` runs a `Flight` per watched bird: on the ground they walk or swim (swans stay on water, ravens and parrots on land or treetops, gulls either; `perch` finds the top), take off when the timer runs out or a player comes within `STARTLE`, circle the island at altitude and descend to a `landing` spot. Punching one (`pluck`) gives 1-2 feathers (again after `PLUCK_AGAIN`), scares it off and hurts it (`Health` 4; killed, it drops feathers). Client: `body` builds a `beast::rig` (wings on `Joint::Wing` flapping or gliding, folded at rest; legs tucked in flight; the swan's long neck).
- `shroomling.rs` — mushroom-man mobs on mushroom islands. Server (`authority`): `muster` spawns a colony (`3 + radius / 8`, replicated `protocol::Hopper { at, yaw, aloft }` + server `Wander`) once, when a player first comes within `WAKE` of a mushroom island's centre (`Colonies`); they are never despawned and are saved with the world (`World::shroomlings`, `lodge`); `wander` only moves those with a player within `SLEEP`, ensures the chunks around each, walks, rests and turns at random, turns back at drops and water and toward home past 0.8 radius, hops now and then and leaps when blocked (`player::slide` with its own `Bulk`). Client (`plays`): `Mold` (box meshes UV-mapped to a tiny painted sprite: spotted red cap, gills, pale body with eyes), `dress` adds them to each `Hopper`, `animate` smooths, swings the feet and stretches the body while aloft.
- `console.rs` — the log on screen: `tap` is a tracing layer (`LogPlugin::custom_layer`) collecting info, warning and error messages into `HEARD`; `post` slides each one in at the top left (warnings yellow, errors red, at most `MOST` lines) and `fade` drops it after `SHOWN_FOR` s. The web release build keeps info logs (`release_max_level_info`) so players see them.
- `crumble.rs` — digging feedback instead of a progress bar: a shell of the dug block's real shape (`mesh::lone`: octagonal logs, models; triangles `shatter`ed into pieces up to 1/8 block), slightly larger than the cell, `contort`ed (swelling waves, squash and stretch, twist), shaking, cracked pieces darkening and popping out as `Aim.progress` grows.
- `loose.rs` — items in the world: Q tosses one of the selected stack (Ctrl+Q all of it) as a replicated `Loose`; `Looks` caches item meshes (`cubic` blocks: a small textured cube; everything else `sliver`: its side tile extruded one texel thick, edge faces per opaque texel, `FLAT` wide); the server (`Tumble`) throws it from the eye, lets it fall, slide and float (`march` with a small `Bulk`), gives it to a player within `GATHER` once its `wait` is over and drops it after `LASTS` s (not saved). `scatter` spawns one (mob drops too). Clients show it still, at a random yaw: cubes resting on the ground, slivers lying flat.
- `water.rs` — water is `Water` (`ExtendedMaterial<StandardMaterial, Swell>`, `water.wgsl`, embedded): glossy, depth tint from the vertex colours, the surface normal from directional sine waves plus two drifting value-noise layers (fading with distance), crests a little brighter. With the camera underwater (`submerge`, PostUpdate) an unlit `Abyss` sphere in the fog colour around the eye hides the sky, and the eye gets the `Submerged` fullscreen pass (`underwater.wgsl`: wobbling refraction, blue-green tint, vignette, faint caustic shimmer) and a short murky teal fog.
- `glance.rs` — combat readouts: `blush` swaps every mesh of a beast or bird struck within `BLINK` s to a reddened copy of its material (`Reddened` cache, `Blushing` keeps the original); `tally` watches every creature's replicated `Health` (`Wounds`: last health, when struck, where) and floats a red `-N` up from it (`Rising`, projected through the camera, fading over `RISE_FOR`); `fell` shows the killing blow when a recently struck creature's `Health` goes away. `target` casts from the eye (`SIGHT`, stopped by blocks) at folk, beasts and birds; the one looked at and any struck within `RECENT` get a `plate` above them (`Plated`) with their name (hostile red, others white) and health bar (`sighted` names them and knows their full health).
- `plate.rs` — world-space labels: a `Plate { text, color, health, at }` entity is a billboard (faces the camera's plane, hidden beyond `SEEN_WITHIN`) whose texture is drawn when the text, colour or health changes: the signs' 3×5 pixel font (`sign::inked`) on a translucent backing, an optional health bar below; `TEXEL` metres per pixel. The clouds sort behind every other transparent (`Cloud::depth_bias`) so plates show in front of them. Player name tags (`figure.rs`, in the player's hue) and creature readouts use it.
- `chat.rs` — text chat: Enter or T opens a line (`Menu::chatting`, which `menu::closed`/`Menu::idle` count as busy so movement and shortcuts pause), Enter sends `Say`, Esc cancels; heard `Said` lines (name in its hue) stack at the bottom left, the last `RECENT` shown for `SHOWN_FOR` s, all `KEPT` while typing.
- `hud.rs` — `SHADE` is the hard 1 px black text shadow; `scale` sets `UiScale` from the window height (720 logical px = 1, quarter steps, never below 1) so every UI element grows with the screen; crosshair, `Notice` line above the hotbar (fades after `ANNOUNCED_FOR`), hotbar (one gray `STRIP` without padding, so the selected outline reaches its edges, `SLOT` 46 px with 40 px icons from `Palette.icons`, the selected slot outlined in `PICKED`) and counts, status line (role/connection, players, position, target, fps, chunks loading), health hearts (9 px drawings at exactly 2x) above the hotbar and a red flash when hurt, block outline (12 edge bars around the target's box: the whole cell, or a model's `model::bounds`, jitter included). `icon_rect(block)` is the rect of a block's icon in the icon atlas.
- `sky.rs` — physical atmosphere; `daylight(hour)` is the light for the fixed `hour`: sun (a large `SUN_DISK`) or, at night, the moon (`MOONLIGHT`, blue), exposure by sun elevation (`DAY_EXPOSURE` 13.6 down to `NIGHT_EXPOSURE` 7.2), haze from day through dusk to night; cascaded shadows, a bluish ambient that rises at night, `lens()` (exposure, ACES, bloom, distance fog that hides the streaming edge). `kindle` gives the `TORCH_LIGHTS` nearest torch edits real, slightly warm point lights (`TORCH_LUMENS`, range 20, lumens scaled with exposure so they read by day in caves too) with an ember emitter.

# Opts
Natively the env var `BLOXY` holds JSON5 `opts::Opts`; in the browser the URL query (`?connect=wss://host:port&name=Ann`, or `?opts={…}` for anything else). `connect` defaults to the build-time env var `BLOXY_CONNECT` (the Pages build sets the hosted server); `?connect=` (empty) plays solo. Fields: `connect` (server URL: guest), `serve: port` (headless dedicated server), `host: port` (play and serve), `name`, `password`, `menu: 'inventory'|'settings'|'profile'|'skin'|'waystones'|'sign'|'map'` (start with the menu open; screenshots then don't wait for a player), `save` (world file; dedicated servers default to `world.json` in the working directory, other roles don't save unless given), `seed` (1), `reach` (view radius in chunks; 9 native, 6 web), `hour` (10), `creative` (starter hotbar and backpack with stacks of building blocks, torches, stations, a boat and buckets; fast digging), `shot: <secs>` (screenshot to `screenshots/shot-$SHOT_NAME.png` once loaded, then exit), `at: [dx, dz]` (spawn offset from the spawn point, on the ground), `yaw`, `pitch` (degrees), `press: [[secs, 'LMB'|'RMB'|'W'|'A'|'S'|'D'|'Space'|'Ctrl'|'Shift'|'Tab'|'Esc'|'E'|'Q'|'V'|'1'…'9'], …]` (taps of 0.15 s; a tap shorter than a frame is released the next frame), `hold: [[from, to, key], …]`, `trader: secs` (first trader ship), `raid: [secs, 'pirates'|'vikings']` (first raid), `weather: 'clear'|'cloudy'|'rain'|'storm'` (fixed weather), `admin: port` (admin command port; 7778 by default when serving or hosting).
e.g. `BLOXY='{shot: 2, yaw: 40, pitch: -15}' SHOT_NAME=valley tools/shot`. Screenshots are the way to check visuals — always look at them.

# Multiplayer
- Dedicated server: `BLOXY='{serve: 7777}' cargo run --features dev`. Browser pages served over https (GitHub Pages) can only open `wss://`, so put the server behind a TLS proxy (e.g. Caddy `reverse_proxy localhost:7777`) and join with `?connect=wss://your.host`. Native clients use `ws://host:7777`.
- Hosting: `.github/workflows/server.yml` builds the server on GitHub Actions (`--profile server`: release without LTO, stripped) on pushes to `master` or the working branch, verifies the host key fingerprint, uploads the binary to `/opt/bloxy/bin/bloxy` as the `bloxy` user (secret `DEPLOY_KEY`) and waits for the `bloxy-restart.path` unit to restart the service. `deploy/setup.sh` is the one-time root bootstrap of the Debian host: ufw (22, 80, 443, 7777), the `bloxy` user and its deploy key (printed for the secret), the `bloxy` service (`serve: 7777`, working dir `/opt/bloxy/world`) and Caddy terminating TLS for `wss://$DOMAIN`. Cloud sessions can't SSH out.
- `tools/duo` runs a dedicated server and two clients under xvfb and screenshots the second seeing the first: the quickest end-to-end check of netcode.
- Movement is client-authoritative; blocks, inventories and player list are server-authoritative.
- The hosted world lives in `/opt/bloxy/world/world.json` (edits, accounts, claims). When generation changes, bump `generate::GENERATION`: the new server keeps claimed chunks from their saved snapshots and drops other edits. `bloxy admin regen [seed]` on the host does the same on demand; deleting the file (service stopped) starts from nothing.
- Admin over SSH: `/opt/bloxy/bin/bloxy admin help` talks to the running service on 127.0.0.1:7778 (look at the world as text maps or PNGs, place blocks, spawn and remove mobs, regenerate). The browser's solo mode doesn't save.
- The UI font has no `−`, `×`, `°` or `…` glyphs: use ASCII.

# Build
Priority is fast incremental builds over runtime speed. Debug builds only; release only when asked.
- `cargo check` to verify compilation; `cargo run --features dev` to play (`dev` = Bevy dynamic linking).
- `tools/shot <name> '<opts>'` builds and screenshots under xvfb.
- Cloud sessions have no GPU: wrap runs in `xvfb-run -a -s "-screen 0 1600x900x24"` (lavapipe, software Vulkan, slow frames).
- Bevy runs without default features: `Cargo.toml` lists only what the game uses. Add a feature there when using a new Bevy part.
- Web build: `trunk build --release` (`index.html`), deployed to GitHub Pages (`.github/workflows/pages.yml`, Settings → Pages → Source: GitHub Actions) on pushes to `master` or the working branch, joining the hosted server by default. Needs WebGPU.
- On a panic or startup failure (including Bevy system param conflicts), rerun with `RUST_BACKTRACE=1`.
- Docs: https://docs.rs/bevy/0.19.1/bevy/ , https://docs.rs/bevy_replicon/0.44.3/bevy_replicon/

# Style
Code structure should mirror the thinking behind it: translate the user's conceptual framework fairly directly into code. Functional-ish.
- Format with `cargo +nightly fmt` (repo `rustfmt.toml` uses nightly-only options). Avoid comments; name things well.
- Order within a file: if A refers to B, A comes after B. Keep related code together.
- Semicolons are a verbosity signal: prefer expressions over statements.
- No `return`, `continue`, `let … else`, or early exits.
- Prefer let chains over nested `if let`/`if` or `.and_then()`.
- Prefer `Option` methods over matching on `Option` (not so for most other enums).
- Prefer `find`, `find_map`, `any`, `fold` over loops with break (socket read loops are the exception).
- Eagerly destructure: `let &Thing { field } = thing()`.
- Domain model with named instances, newtypes and associated consts.
- No more function-calls-function indirection than needed.
- ECS: merge components that always co-occur. Name components by behaviour, not entity.
